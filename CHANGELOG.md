# Changelog

## v0.1.3 - Unreleased

### Cached tree geometry

- Replaced per-triplet DendroPy subtree copies with a cached per-tree geometry lookup, for the gene trees and the species tree alike. Each tree is walked twice -- pre-order for a parent/edge-length array, post-order for a pairwise LCA table -- and each triplet's topology and tree height then follow from three table lookups and a few short walks up the parent chain, instead of `extract_tree_with_taxa_labels` copying the tree once per (triplet, tree) pair. The cache is built once in the parent and inherited by workers copy-on-write, so a worker holds one shared copy rather than reparsing every gene tree per triplet chunk.
    - The topology comes from LCA node *identity* rather than any distance comparison, so it is exact and a zero-length internal branch cannot be mistaken for a polytomy; heights are summed along the short path from the triplet's own MRCA rather than as a difference of two root depths, which avoids the cancellation that form would introduce.
    - On the species tree the same cache also yields each triplet's induced subtree, whose Newick the `species_tree` column carries -- child order and the root edge that unifurcation suppression collapses into it included.
    - `trees.extract_triplet_subtree` and `inference.observation_from_subtree` remain as the DendroPy reference implementation. No run calls them; the parity tests hold the cached path to agreement with them.
    - Measured over 684,000 (triplet, gene tree, strategy) comparisons the two paths agree bit-for-bit on the `A`, `B`, `C`, `SIS` and `INT` strategies and to one unit in the last place on `AVG`, with no topology or skip-decision differences, and the species Newick matches byte for byte on 112,706 triplets. The extraction step alone is about 100x faster and a full 91,881-triplet run over 1,475 gene trees 3.1x faster in wall and CPU time, with counts, topologies, test statistics, p-values and the decision gate all bit-identical.
- Changed `preflight_data_check` to replay that cached path on both tree sides instead of copying a subtree per triplet, making the gene-tree stage about 50x faster over 1,475 gene trees. It therefore reports the skip decisions a run would actually make. The triplet cap, previously a fixed 1,500, is now the `preflight_triplet_cap` key (`--preflight-triplet-cap`, `0` for no cap) and defaults to 15,000, spending part of that headroom on coverage: 15,000 triplets over those 1,475 gene trees now check in about 25 s, against 11 s for 1,500 -- ten times the triplets for 2.4x the time, since parsing the gene trees and building their geometry is a fixed cost the smaller cap was mostly paying for anyway.
    - Four reported categories are gone because the geometry path cannot reach them: `triplet.invalid_leaf_count` (the Newick parser refuses a duplicate taxon label before any check runs), `triplet.abc_mapping_mismatch` and `triplet.sister_mrca_missing` (the sister pair is read off LCA identity, so it is one of the three ABC pairs by construction and its MRCA always exists), and `species_triplet.subtree_missing` (every label reaching that check is already known to be a species-tree leaf, so an unresolved triplet is the only rejection left and it reports under `species_triplet.invalid_rooting_or_topology`). `triplet.subtree_extraction_failed` becomes `triplet.geometry_unavailable`, and `triplet.unresolved_rooted_sister_pair` -- the one that finds real problems -- is unchanged.
    - Added a `usable_pairs` report line accounting for every triplet/gene-tree pair the check looked at: those a run could measure (`triplet.resolved`), those it would drop as unresolved, and those skipped because the gene tree lacks one of the three taxa (`triplet.taxa_absent_from_gene_tree`). That last group was previously invisible -- skipped with no counter and no issue -- so a report could say nothing was wrong while a large share of the pairs it counted as checked would never be measured.

### Skipped and reused computation

- Added `pipeline_mode` (`--pipeline-mode`, default `efficient`), which stops measuring a triplet once the decision cascade has settled it. The permutation direction test is only consulted at the third gate, but the point estimate previously ran it for every triplet -- 2,500-25,000 studentized resamples each -- and discarded the result wherever an earlier gate had already decided the call. `efficient` skips it there under every correction method, and under `no`/`bfn` also skips the tree-height test below a settled count gate; `detailed` computes all three gates for every triplet.
    - **Results are identical either way, under every correction method**: not merely the classifications but every value the cascade reads, bootstrap votes included. Every supported correction is monotone, so a gate that failed on the raw p-value cannot clear on the corrected one and the skipped test could never have been reached; and the permutation p-values are corrected inside each test rather than across triplets, so an unrun direction test moves no other triplet's numbers. Under `no`/`bfn` the gate is judged on the exactly corrected value, `p × n_triplets`, so only tests the run-wide pass would find unread are skipped; under the rank-based methods it is judged on the raw value, which is the conservative side.
    - The tree-height family is always the triplet count. Under `no`/`bfn` a skipped member is still corrected by that count, never by the number measured -- shrinking the family to the survivors lowers their corrected values and moves classifications past the tree-height gate -- and under `holm`/`fdr_bh`/`fdr_by` the test is measured for every triplet, because a rank-based correction reads every member's value. Neither family changes with the mode.
    - Skipped triplets leave the `perm_*` columns empty and report `perm_note: direction_test_not_consulted`, which distinguishes a deliberate skip from a guard, and under `no`/`bfn` leave the tree-height columns empty below a settled count gate. `metrics.txt` names the mode, says what it skips under the run's correction, and counts the skipped tests.
- Changed the equivalence (TOST) step to ride on the direction test's own resamples instead of drawing two more full permutation passes. Its two nulls sit an equivalence margin either side of zero, which is a constant added to one group, so a shifted permutation's studentized statistic follows from the unshifted power sums plus two extra reductions over the same gather. The step now costs a fraction of a pass rather than two, and both questions are answered at the same Monte Carlo resolution by construction. `perm_p_tost` values differ from before: they are a different Monte Carlo realization of the same quantity, since the reused permutations are not the fresh draws the two-pass version made.
- Fixed `--no-bootstrap` running the full bootstrap and discarding it. `config["bootstrap"]` reached only the TSV header, never the inference layer, so disabling it dropped the columns while still paying ~100 iterations per triplet. It now skips the iterations, under `pipeline_mode: detailed` too: declining to skip work the cascade cannot consult is not the same as reinstating work that was switched off.

### Parallelization

- Removed `parallelization_mode` (`--parallelization-mode`) entirely. Its `gene` mode parallelized per-gene-tree subtree extraction while running inference serially in the parent, which inverted the run's cost profile once extraction stopped dominating it -- and `auto` selected it above 3500 gene trees, so the largest runs got the least useful mode. With `gene` gone, `auto` and `taxon` named the same strategy: triplet chunks are the only unit worth distributing, because a run's cost is per-triplet inference. Parallelism is controlled by `--processes` alone.

### Multiple-testing correction

- Removed `fdr_tsbh` from `p_value_correction`, leaving `no`, `bfn`, `holm`, `fdr_bh` and `fdr_by`. It was the only method whose adjusted p-value can fall *below* the raw one, and carrying that exception required a monotonicity predicate, a `short_circuit` flag on the bootstrap policy, and a branch at every skip site -- all now gone, and every short-circuit is unconditional.
- Moved every decision to the run-wide pass. The stream now returns measurements only -- counts, the tests' statistics and raw p-values, the direction and the bootstrap votes -- and `_apply_triplet_result_p_value_correction` sets the corrected p-values, both significance flags, the classification, its gate and `bootstrap_value` in one place, once every triplet's p-values are in hand. The stream still judges a gate where the efficient mode needs to know whether a downstream test could be read, but records no decision. Previously each triplet was classified provisionally on raw thresholds as it streamed and the pass overwrote that; a lone triplet was also decided where it was analyzed. `analyze_triplet`, the Newick-taking wrapper that only the tests called, is removed; `analyze_triplet_from_observations` is the per-triplet unit and returns an undecided result.

### Result columns and reporting

- Renamed `perm_stat_ci_low`/`perm_stat_ci_high` to `bootstrap_stat_ci_low`/`bootstrap_stat_ci_high`. The interval is a bootstrap percentile interval on the studentized difference, computed inside the bootstrap loop rather than by the permutation test, and the old prefix implied otherwise. With `--no-bootstrap` it is now empty, which is what the orchestrator guide already documented.
- Removed the shape diagnostics from `summary_statistics.tsv`. The fifteen `concordant_*`/`discordant1_*`/`discordant2_*` shape columns were written there whenever `shape_diagnostics` and `generate_summary_stats` were both set. That file is consumed as a machine-learning feature matrix, and these columns are undefined for groups below their observation floors -- a group under 20 observations has no modality p-value or moments, and an upper decile under 10 points has no tail index -- so they punched holes in rows that the trainers reject outright. They remain in the results TSV as `con_*`/`dis1_*`/`dis2_*`, where nothing consumes them programmatically.
- Added the run's seed to `metrics.txt` as `Seed: <n> (configured|generated)`, the resolved pipeline mode with what it skips under the run's correction, and the counts of triplets clearing the count gate and the tree-height gate.

### Configuration keys

- Moved the RNG seed out of `bootstrap_options` into a run-wide `seed` key with a `--seed` flag, replacing `bootstrap_seed`/`bootstrap_options.seed`. The old name understated its reach: one configured seed already drove every random draw in a run -- the permutation direction test, the bootstrap resampling, the bootstrap's own permutations, and the modality bootstrap in the shape diagnostics all take independent child streams spawned from `(seed, triplet)` -- so the key is named for what it seeds. There is no other source of randomness in the orchestrator.
    - When none is configured, one is drawn once for the run and reported, instead of each triplet drawing independently from system entropy. That makes an exploratory run reproducible after the fact: pass back the value its own metrics file reports.
- Added `species_rename_map` (`--species-rename-map`), an optional two-column TSV or YAML mapping from the taxon labels used in the species and gene trees to the names that should appear in the outputs. The rename is applied to both tree sets as they are read, so the results TSV, `summary_statistics.tsv`, the processed tree files, and the consolidation matrices and plots all carry the display names without any writer needing to know about the map. Taxa absent from the map keep their tree labels, and the outgroup and any triplet-filter entries are given in the trees' own labels and mapped along with them. A map that names a label twice, or maps two labels onto the same display name, is rejected -- the latter would collapse two taxa into duplicate tree labels and fail later in the Newick parser with no reference to the map.

### Hyperparameter tuning

- Made Weights & Biases logging optional for `ghostparser.ml.hyper_tune`. `hyperparameter_tuning.use_wandb` is a boolean defaulting to `false`, so a config that never mentions W&B runs locally and only a config that asks for it logs to a run; a non-boolean is still rejected. Previously the tuner initialized W&B on every run and `import wandb` at module import time made `hyper_tune` unimportable without the package.
    - `wandb` is imported lazily and only when `use_wandb: true`, and has moved out of the `ml` extra into its own `wandb` extra -- `pip install .[ml]` no longer pulls it in, and `pip install .[ml,wandb]` restores the previous dependency set. `wandb_detailed_payloads` now requires `use_wandb: true` instead of being silently ignored.
    - Under `use_wandb: true` the bulk outputs are logged to the run rather than duplicated on disk: `hyper_tune_results.json`, `hyper_tune_results.tsv`, `hyper_tune_parameter_marginals.tsv` and `predictions.tsv` become the `tables/ranked_candidates`, `tables/parameter_marginals` and `tables/predictions` W&B tables plus a `results_json` run-summary field, leaving only `hyper_tune_best_model.pkl`, `hyper_tune_results.txt` and `hyper_tune_search_report.png` in the output directory. `use_wandb: false` still writes everything locally. The report's `Artifacts:` block, the `artifact_paths` key and the paths returned by `tune_hyperparameters` list only what was actually written, and the run summary gains `local_artifact_paths` and `bulk_artifacts_written_locally` in place of `results_json_path`/`results_tsv_path`/`predictions_path`, which would otherwise have named absent files.
    - Added `sample_configs/hyperparameter_tuning_multi_knn.json` alongside the random-forest YAML sample, so a runnable tuner config ships for each config format and each supported model.
- Expanded the local tuning report so a search can be navigated without W&B. `hyper_tune_results.txt` listed only the best candidate, a `top_k` line per candidate, and timings; it now echoes the searched `search_space`, renders the top candidates as an aligned table, and adds a per-parameter value summary plus a guidance block that ranks parameters by how far they moved the objective and flags a winning value at the edge of the searched range. New alongside it: `hyper_tune_parameter_marginals.tsv` and a `hyper_tune_search_report.png` figure, an `elapsed_seconds` column in `hyper_tune_results.tsv`, and `use_wandb`, `parameter_marginals`, `parameter_influence` and `artifact_paths` in `hyper_tune_results.json`.

### Trainer confusion matrices

- Changed both confusion-matrix figures written by `random_forest` and `multi_knn` to be readable without counting cells.
    - The 64-class heatmap moves from raw counts on a per-run colour scale to row-normalized fractions on a fixed 0-1 scale: each cell is the share of its true class predicted into that column, so every populated row sums to 1 and the diagonal reads as per-class recall. The old scale ran to whatever the largest count happened to be, which depended on how many test rows each class drew. Zero cells are painted at the low end like any other value, so the grid reads as one continuous surface. The counts under `confusion_matrix_64_classes` in the metrics JSON are the same, in the class order below.
    - It labelled only every fourth class on each axis, so 48 of the 64 rows and columns had no tick and a class had to be identified by counting inwards from the nearest one; all 64 are now labelled on both axes, under the titles `Predicted 6 binary class` and `True 6 binary class`, and both axes run by the number of set bits -- `000000`, then the six single-bit classes, up to `111111`, lexically within a count -- rather than in binary order, which had scattered the single-bit classes across the whole range. A class therefore sits on the diagonal opposite itself and the metrics JSON's `class_labels` and `matrix` follow the same order.
    - The six per-bit panels were titled with the raw label slug (`inflow_into_A_from_C`) and now read as prose (`Inflow into A from C`) via a new `ml_utils.format_bit_label_title`. Only the first character is upper-cased -- `str.capitalize` would lower-case the rest and rename the taxon its trailing letter identifies.

### Trainer parameters

- Changed the `model.max_features` default from `sqrt` to `null`, so every split considers every feature unless the key says otherwise. The value no longer needs writing at all for the common case, and a config that wants scikit-learn's own classifier default sets `sqrt` explicitly.
- Fixed `model.max_features` and `model.class_weight` reaching scikit-learn unvalidated. Both were raw passthroughs, so a config error surfaced only as the estimator's own message at fit time. Every value is now checked in config against what scikit-learn accepts (see [CONFIG.md](CONFIG.md) for the accepted forms), and a rejected one names the dotted config location, the value received, every accepted form, and how null is written -- YAML reads the bare word `None` as a string, and that string is the value users reach for first; `auto` gets its own message saying scikit-learn removed it in 1.3 and pointing at `sqrt`. `hyperparameter_tuning.search_space` candidates are validated the same way, so a bad entry is reported before the search starts.
    - Corrected the matching [CONFIG.md](CONFIG.md) entries, which described `max_features` as "string|int or null", said `null` "keeps the estimator's default split-feature behavior" when it in fact means *every* feature at each split, named none of the valid strings and omitted float support; `class_weight` likewise did not mention `balanced`, `balanced_subsample`, or the per-label list form.

### Removed and deduplicated code

- Removed dead and duplicated internals across the package, with no change in behaviour: `inference.compute_tree_height_statistic`, `inference._build_triplet_np_rng`, `triplet_utils.rank_topologies_by_frequency` and `tuning_report._better`, none of which had a caller, and the duplicated trainer helpers described below.
- Deduplicated the trainer internals with no change in behaviour: `hyper_tune.py` imports the seven validators it had copied from `ml/config.py` and the config trunk; the byte-identical confusion-matrix builder and CLI parser/resolver in both trainers become `ml_utils.build_confusion_matrices` and `ml/config.py`'s `build_trainer_argument_parser`/`resolve_trainer_runtime_args`; eleven one-line wrappers in `random_forest.py` that renamed `ml_utils` functions without changing them are gone, their call sites naming `ml_utils` directly as `multi_knn.py` already did; and `_validate_optional_positive_int`, which rejected `None` despite its name and return type, splits into `_validate_positive_int` and a genuinely optional variant. Each deleted validator was replayed against the import that replaced it over 344 input combinations with no difference.

### Tests and documentation

- Categorized every test with a pytest marker so one part of the code can be checked without the whole suite: `core` (the statistics and decisions; added automatically to any test not otherwise marked), `config` (loaders, normalizers, validators), `output` (what was written -- files, columns, report fields), `integration` (an entry point driven end to end), and the existing `parity`. A test may carry several. `config` runs in about 5 s and `output` in about 15 s against 47 s for everything; `core` stays the slow one, since two `holm` cases run the full deferred bootstrap.
- Stopped pinning individual config defaults. The orchestrator config tests asserted twenty of them one by one and three tests existed to read a single key back; those are replaced by two invariants -- CLI mode and config-file mode resolve to identical dicts, and `orchestrator_full.yaml` names every runtime key at its default -- and the one-key rejection tests fold into a single parametrized case list per loader. The trainer samples gain the loads-cleanly contract the orchestrator and tuner samples already had. 448 test cases become 437.
- Audited the suite against the repo's own test-scope rules and dropped what it was not supposed to assert: the preflight report's attribution lines matched down to their column padding, the stdout and report wording inside three other tests, and six assertions in the trainer smoke tests that named artifacts an earlier version wrote and nothing writes now. `test_train_random_forest_smoke` also asserted `timings_seconds.total >= 0`, which elapsed wall time satisfies unconditionally, and now asserts the field contract instead.
- Replaced the bootstrap-budget test's pinned divisor (`(2500, 25000) -> (500, 5000)`) with two property tests: an iteration's budget is strictly below the configured one wherever there is room to divide, never below one resample and never inverted, and neither end shrinks as the configured budget grows. Setting the divisor to 1 fails five of the six parametrized cases, so it stays tunable without the regression going unnoticed.
- Added parity coverage for the cached geometry -- eleven tree shapes across the six tree-height strategies, a hand-derived five-taxon case, and an 84-triplet sweep of a nine-taxon tree -- plus tests for the rename map and the preflight pair accounting, each with its inputs and the derivation of every expected value recorded in [tests/TEST_IO.md](tests/TEST_IO.md). `test_every_supported_correction_is_monotone` now asserts the property over the whole choice list rather than a fixed set of names, so re-adding a non-monotone method fails immediately instead of silently breaking the skips.
- Gave the ML suite the docstrings the rest of the suite already had, each stating what its test pins rather than restating the test's name.

## v0.1.2 - August 18, 2026

### Architecture

- Rewrote `ghostparser.orchestrator` as a package running one fused streaming pass: triplet extraction and inference share a single loop, with no intermediate `unique_triplets_gene_trees` file and no Newick round-trip between them. This removes the memory blowup on large gene-tree sets; a 3000-gene-tree / 35-triplet serial run went from roughly 44s to 25s.
    - Replaced the `tree_parser` and `triplet_processor` submodules and their standalone CLIs with internal modules of the package, making `python -m ghostparser.orchestrator` the single analysis entry point.
    - Moved `ghostparser/introgression_mapper.py` to `ghostparser/orchestrator/consolidation.py` and dropped its standalone CLI. Consolidation is the orchestrator's final stage and its input is the in-memory results list, so there was nothing for a command line to point at that the orchestrator did not already produce; `generate_introgression_maps` takes `TripletPipelineResult` objects only. `tests/test_introgression_mapper.py` moved to `tests/orchestrator/test_orchestrator_consolidation.py`.
    - Removed the custom statistical backend — the discordant count test, KS test, and p-value corrections always use SciPy/statsmodels, and `stats_backend` is gone — along with the parquet/intermediate-file options (`triplet_output_format`, `input_format`, `parquet_partitions`, `parquet_compression`).
- Added `--parallelization-mode {auto,taxon,gene}`: `taxon` dispatches triplet chunks across workers, `gene` parallelizes subtree extraction within one triplet, and `auto` picks from input size (`gene` below 15 ingroup taxa or above 3500 gene trees, else `taxon`). Bootstrap values stay deterministic under a fixed `bootstrap_seed`, so every mode agrees exactly.
- Restructured configuration into a shared trunk plus per-module ownership. `ghostparser/config.py` keeps only the helpers that behave identically for every consumer (460 lines down to 188); `ghostparser/orchestrator/config.py` and `ghostparser/ml/config.py` own their defaults, choices, and validators, so their settings can diverge. Both CLIs share `cli_config.resolve_cli_or_config_args` for config-file-wins precedence.

### Statistical inference

- Replaced the final inference step: the direction of the concordant-versus-discordant1 tree-height difference comes from an adaptive Welch-studentized permutation test (`ghostparser/orchestrator/permutation.py`), which fully replaces the median sign comparison rather than sitting alongside it, so the call carries a p-value and a confidence statement instead of following any numerical difference however small. Resampling continues until a confidence interval around the p-value excludes `alpha_perm` or the budget is spent, and samples too small or too degenerate to support the test are reported with a reason rather than given a direction. See [ORCHESTRATOR.md](ghostparser/orchestrator/ORCHESTRATOR.md#the-statistical-tests) for the method and its citations.
    - Added `alpha_perm` (default `0.05`, CLI `--alpha-perm`) and the config-file-only `permutation_options` block (`min_resamples`, `max_resamples`, `ci_method`).
    - Replaced the `unresolved` classification with `ambiguous`, which also covers the case where the KS test separates the height distributions but the permutation test finds no directional evidence.
- Added TOST equivalence testing, splitting the permutation outcome into `equivalent` (the mean heights were shown to differ by less than the margin) and `inconclusive` (nothing was established either way). Both still classify the triplet as `ambiguous`; the distinction says whether the data supported a claim of similarity or merely failed to support a difference. The margin is a Cohen's *d* of 0.5 — half a pooled standard deviation — tested by two one-sided permutation tests against shifted nulls and reported in `perm_p_tost`.
- Added a `decision_gate` column naming the test that produced the classification (`DCT`, `THT`, or `PERM`). It is derived in the same pass as the classification — `_classify_introgression` returns both — so the two cannot disagree. The point estimate computes all three tests for every triplet, so the `perm_*` columns are populated even where the cascade stopped earlier; previously nothing in the row distinguished a `perm_decision` that produced the classification from one that was merely recorded, which made rows such as a non-directional `perm_decision` beside `classification = inflow_introgression` read as self-contradictory.
- Changed one orchestrator default: `p_value_correction` from `no` to `bfn`.

### Multiple-testing correction

- Fixed bootstrap iterations measuring a different decision rule than the classification they support. Iterations compared *raw* DCT and KS p-values to `alpha_dct`/`alpha_ks` while the reported classification came from *corrected* ones, so `bootstrap_value` answered a question nobody asked — real rows showed `classification = inflow_introgression` alongside `all_bootstrap[inflow_introgression] = 0`. Every iteration is now judged against the same corrected thresholds as the point estimate.
    - `no` and `bfn` are applied inline during the stream; `holm`, `fdr_bh`, and `fdr_by` park their raw per-iteration p-values and are corrected across triplets afterwards, one family per iteration index.
    - `fdr_tsbh` takes the same deferred path but runs every test unconditionally, since two-stage BH can lower a p-value and so cannot license skipping a gate. The other four provably cannot, which is what lets them skip the direction test once a raw gate has failed — the run's largest cost centre. See [ORCHESTRATOR.md](ghostparser/orchestrator/ORCHESTRATOR.md#correction-inside-the-bootstrap) for the per-method argument and citations.
- Changed the results TSV to omit the four `*_corr` columns under `p_value_correction: no`. With no adjustment applied they duplicated the raw p-value sitting beside them, and a header reading `dct_p_val_no_corr` implied a correction that had not been performed. The raw p-values and the `dct_significant`/`ks_significant` flags are written regardless, so nothing the classification rests on is lost; a `no` run writes 32 columns instead of 36.
- Fixed `p_value_correction: no` in a YAML config failing validation. YAML 1.1 resolves the bare word `no` to boolean `False`, so the value never reached the validator as a string and the run aborted with a message listing `no` among the valid choices. Boolean values are now mapped back to the choice they were written as (`no`/`off`/`n`/`false` and `yes`/`on`/`y`/`true`), so the unquoted spelling works for any enumerated field. The error message also names the value it received.

### Result columns and reporting

- Changed the results TSV columns: `summary_con`/`summary_dis` are replaced by the `perm_*` family (statistic, raw and corrected one-tailed p-values, `perm_p_tost`, resample count, convergence, `perm_null_skew`, `perm_note`, `perm_decision`). No per-group mean or median columns are written there at all — the direction comes from the p-values, and descriptive per-group statistics belong to `summary_statistics.tsv`. Removed the `summary_statistic` key and its `--summary-statistic` flag, which no longer selected anything.
    - `perm_null_skew` reports the permutation null's asymmetry as the sample skewness of the null, accumulated from running power sums so batches are still discarded, for every test that resampled whatever it decided. It never drives a decision; a large magnitude says a few extreme heights in the smaller group dominate the resampling.
- Added `perm_stat_ci_low` and `perm_stat_ci_high`: a bootstrap-percentile interval on the studentized mean difference at the `1 - 2 * alpha_perm` level, which is the level at which an interval and a one-sided test at `alpha_perm` agree. Unlike the binomial intervals the stopping rule places around the p-values, this one is an interval on the effect, so it says how large the separation might plausibly be rather than only whether it cleared a threshold.
- Added `shape_diagnostics` (config-file only, default `false`), which appends fifteen columns describing the shape of each height group: a KDE mode count, a Silverman critical-bandwidth modality p-value, skewness, excess kurtosis, and a generalized-Pareto tail index over the upper decile. They are descriptive and never enter a classification.
    - The modality test is used rather than a raw mode count or a BIC-selected Gaussian mixture because both of those mistake skew for structure — on 400 unimodal draws a mode count at the default bandwidth reports 3 modes for an exponential and 4 for a Pareto, and BIC selects two or more components for every skewed unimodal family tried. Silverman's test rejects none of them, at the price of needing roughly three standard deviations of separation to detect a real mixture.
    - The tail index uses a peaks-over-threshold generalized-Pareto fit rather than the Hill estimator, which is non-negative by construction and so cannot represent a bounded tail.
    - Off by default because the modality bootstrap costs about 0.2s per group, roughly 0.6s of extra CPU per triplet. The diagnostics are measured once per triplet from the observed heights; bootstrap iterations never recompute them.
    - When `generate_summary_stats` is also set they are repeated in `summary_statistics.tsv` under that file's full-word group names (`concordant_*`/`discordant1_*`/`discordant2_*`), so they are available as features to the ML trainers.
- Fixed the `discordant1_*` and `discordant2_*` columns of `summary_statistics.tsv` naming the wrong gene trees. They were hardwired to the canonical `BC|A` and `AC|B` topologies while the `dis1_topology` column and every statistical test use whichever discordant topology is more frequent, so on any triplet where `AC|B` outnumbered `BC|A` a `discordant1_*` feature described a different set of gene trees than its own row claimed — which also mislabelled the features `ghostparser.ml` trains on. The roles are now resolved per triplet from the observed counts.
- Changed `metrics.txt` to report guarded and unconverged permutation tests as counts rather than naming every triplet. On a real run those lists ran to hundreds of lines each and buried the rest of the log, while every per-triplet detail they carried is already in the results TSV under `perm_note`, `perm_converged`, and the `perm_p_*` columns. The guarded line still breaks its count down by which guard fired, since the four mean different things.

### Consolidation figure

- Changed the figure to use `cividis` throughout.
